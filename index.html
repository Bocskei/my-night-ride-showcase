ABOUT THE PROJECT

What is My Night Ride?

My Night Ride is a mobile game built in Unity and C#, combining car movement with ball-and-brick gameplay across multi-wave levels.

The player launches balls, clears obstacles, manages limited lives and races against the clock. Beyond the core gameplay, the project includes rival cars, power-ups, progression and upgrades, an overworld level system, dialogue, scoring and rewards.

The project also integrates Unity Ads as part of its mobile functionality.

GAMEPLAY & SYSTEMS

Core systems

Wave-Based Level Flow

Each level is made up of multiple waves. Clearing the current wave triggers a transition into the next section, while completing the final wave moves the game into a level outro and then back into overworld progression.

The flow coordinates multiple systems including balls, rival cars, dialogue, race timing, gameplay state and level completion.

Ball & Brick Gameplay

The player launches balls through touch input and uses them to destroy obstacles across each wave. Ball lifecycle, starting ball count, gameplay state and transitions between waves are handled through dedicated gameplay systems.

Rival Cars

Rival cars add a chase/racing layer on top of the brick-destruction gameplay. Their behaviour interacts with level state, collisions, pausing, wave progression and failure conditions.

Overworld & Persistent Progression

Outside individual levels, the game uses an overworld for level selection and unlocking. Persistent systems include currency, upgrades, unlock state and regenerating overworld lives.

The upgrade shop modifies gameplay values such as car speed and other player or ball attributes, with progression stored between sessions.

Dialogue & Sequenced Gameplay

Dialogue, transitions, car movement and other multi-step gameplay sequences use asynchronous flows. UniTask is used for these sequences instead of relying on deeply nested coroutines.

TESTING APPROACH

Testing during development

Testing and debugging are part of the development process rather than something added only at the end. New features are tested both in isolation and as part of the wider gameplay flow.

Functional Testing

Core behaviours such as input, ball lifecycle, wave completion, upgrades, level failure and progression are checked against their intended behaviour.

Integration Testing

Systems are tested together because gameplay state, timing, rivals, balls, input, dialogue and transitions frequently affect one another.

Regression Testing

Changes are retested against previously working flows, especially around pause/resume, retry behaviour, wave transitions, Android lifecycle events and level completion.

Runtime Debugging

Unity Console, stack traces and Android Logcat are used to investigate runtime behaviour and Android-specific issues.

TECHNICAL ARCHITECTURE

Project Architecture

My Night Ride separates gameplay, progression, input, saving and level state into dedicated systems. The diagrams below show selected parts of the project architecture and how the main systems communicate.

Input Separation

GameplayInputRouter handles mobile touch interpretation, while PlayerController applies car movement.

Progression Separation

UpgradeService reads persistent upgrade data and exposes gameplay values such as car speed, ball damage and starting ball count.

Gameplay State

GameplayPauseService owns pause state and broadcasts pause/resume events to other systems.

Level Flow Coordination

LevelStateController coordinates wave completion, dialogue, rival behaviour, race timing and level completion without implementing those systems directly.

Services & Game State

Dedicated services handle upgrades and progression, overworld lives, gameplay lives, ball management, rival cars, pause state, race timing, dialogue, save data and level state.

Global and scene-specific systems are exposed through GameServices. Gameplay services are created when the gameplay scene is initialized and cleaned up when it is destroyed.

Custom Update Flow

Many systems implement observer interfaces such as IUpdateObserver and IFixedUpdateObserver and register with a shared UpdateManager, reducing reliance on individual Unity Update() methods.

Events & Async Sequences

Gameplay state changes such as pausing, level completion, life loss, dialogue progression and rival events are communicated through events where appropriate.

UniTask is used for dialogue playback, wave transitions, level outros and car movement sequences.

EXAMPLE

Gameplay values through progression services

GameServices.Upgrades.GetFloatValue(UpgradeType.CarSpeed)

Gameplay systems can read progression values without needing to know how upgrade data is stored internally.
